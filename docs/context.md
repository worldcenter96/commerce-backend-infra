# 1. 프로젝트 개요

| 항목 | 값 |
|---|---|
| 상태 | Approved |
| 버전 | 1.0 |
| 날짜 | 2026-11-13 |
| 작성자 | 박가온누리 |

## 1.1 프로젝트 목적
Spring Boot 기반 의류 커머스 플랫폼을 AWS 환경에 배포하고, Terraform을 통해 인프라를 코드로 관리


## 1.2 프로젝트 범위
| 항목 | 내용 | 
|---|---|
| 프로젝트 | 의류 커머스 플랫폼 인프라 구축 |
| 배포 환경 | dev, staging 제외 prod만 구축 |
| AWS 리전 | 서울 (ap-northeast-2) |
| 프로젝트 성격 | 애플리케이션 MVP 확인용 단기 인프라 배포 |
| 인프라 관리 | Terraform, state는 local로 관리 |
| 구축 대상 | 애플리케이션 운영에 필요한 AWS 인프라 |

본 프로젝트는 실제 상용 서비스의 대규모 트래픽을 처리하는 것을 목표로 하지 않는다.


# 2. 애플리케이션 정보

## 2.1 서비스 구성
커머스 플랫폼은 다음 세 가지 애플리케이션으로 구성된다.
| 서비스 | 설명 | 도메인 |
|---|---|---|
| admin | 사이트 관리자 서비스 | admin.imcommerce.shop |
| b2b | 의류 판매자 대상 서비스 | b2b.imcommerce.shop |
| b2c | 의류 소비자 대상 서비스 | b2c.imcommerce.shop |

세 서비스는 각각 독립적으로 배포할 수 있어야 한다.


## 2.2 기술 스택
| 구분 | 기술 | 
|---|---|
| Backend | JDK 17 |
| Framework | Spring Boot 3.4.0 |
| Database | MySQL 8 |
| Cache | Redis OSS 7 |
| 운영체제 | Ubuntu 24.04 LTS |
| 애플리케이션 실행 | Jar |
| 로그 수집 | Grafana Alloy |
| 로그 저장 | Grafana Loki |
| 모니터링 | Grafana |
| 애플리케이션 레포지토리 | Github |
| CI | Github Actions |

기존 애플리케이션의 기술 스택을 유지하며, 애플리케이션 코드의 대규모 변경은 프로젝트 범위에 포함하지 않는다.


# 3. 요구 사항

## REQ-01. 외부 사용자 서비스 접근
- Admin, B2B, B2C 서비스는 각각 지정된 도메인을 통해 접근할 수 있어야 한다.
- 외부 사용자와 애플리케이션 간 통신은 HTTPS를 사용해야 한다.
- HTTP 요청은 차단해야 한다.
- 외부 사용자가 접근할 수 있는 고정 Public IP가 필요

## REQ-02. 애플리케이션 실행
- 서비스별 독립 배포가 가능해야 한다.
- 서비스별 별도의 서버로 배포되어야 한다.
- 애플리케이션 프로세스가 정상적으로 실행되는지 확인할 수 있어야 한다.

## REQ-03. 데이터베이스
- 데이터베이스는 외부 인터넷에서 직접 접근할 수 없도록 보호해야 한다.
- 애플리케이션 서버와 인프라 관리자만 데이터베이스에 접근할 수 있어야 한다.
- 데이터 보존 및 복구 방안은 현재 프로젝트에서 논의하지 않는다.

## REQ-04. 캐시
- Redis는 외부 인터넷에서 직접 접근할 수 없도록 보호해야 한다.
- 애플리케이션 서버와 인프라 관리자만 Redis에 접근할 수 있어야 한다.

## REQ-05. CI/CD
- Admin, B2B, B2C 서비스를 개별적으로 배포할 수 있어야 한다.
- 배포 성공 및 실패 여부를 확인할 수 있어야 한다.

## REQ-06. 로그 및 모니터링
- 애플리케이션 로그를 수집할 수 있어야 한다.
- 서비스별 로그를 구분하여 조회할 수 있어야 한다.
- 애플리케이션 오류를 확인할 수 있어야 한다.

## REQ-07. 보안
- AWS 리소스는 필요한 최소 권한으로 접근하도록 구성해야 한다.
- 데이터베이스와 Redis의 외부 직접 접근을 제한해야 한다.
- 비밀번호, API 키 등 민감한 정보가 Git 저장소에 노출되지 않아야 한다.
- 서비스 운영에 필요한 네트워크 통신만 허용해야 한다.
- 인프라 관리자는 Bastion을 통해서 내부 인프라에 접근이 가능하다.

## REQ-08. 네트워크
- 애플리케이션 서버, 로그 모니터링 서버 등은 외부와 통신이 가능해야 한다.


# 4. 프로젝트 제약조건

## 4.1 일정 및 운영
- 단기간에 구축하고 검증할 수 있는 MVP 수준의 인프라를 목표로 한다.
- 운영 복잡도를 최소화한다.
- 요구사항에 없는 고가용성 및 자동 확장 기능은 필수로 간주하지 않는다.
- 장애 발생 시 복구 방식은 현재 프로젝트에서 논의하지 않는다.
